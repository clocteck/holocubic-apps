Workflow

从想法到社区上架

保持依赖简单、资源占用可控，并在真实 Cubic 设备上验证启动、交互和退出。

01创建仓库

新建公开 GitHub 仓库，或参考 clocteck 应用库中的现有项目。

02编写应用

以 main.lua 作为入口，准备图标、多语言名称和应用介绍。

03设备测试

在 320×240 屏幕和实际手柄上测试，确保能正常退出并释放资源。

04邮件提交

把应用 GitHub 地址发到 sales@clocteck.com，等待兼容性与安全审核。

最小应用结构

一个基础应用只需要元数据、Lua 入口和 PNG 图标。如果需要 Web 管理页，可增加 main.html。

my-cubic-app/
├── app.info       # 应用元数据
├── main.lua       # Lua 入口
├── main.png       # 应用图标
├── info.html      # 详情介绍（可选）
└── main.html      # WebUI（可选）
github.com/clocteck/holocubic-apps

app.info 基础写法

字段使用 key = value 格式。社区应用必须标注运行类型、内容分类和社区归属。

name = My Cubic App
name_zh_cn = 我的 Cubic 应用
name_zh_tw = 我的 Cubic 應用
name_en = My Cubic App
name_ja = My Cubic App

icon = main.png
version = 0.1.0
kind = app
category = tool
catalog_scope = community
entry = main.lua

description = A concise Cubic app
description_zh_cn = 一个简洁的 Cubic 应用
description_zh_tw = 一個簡潔的 Cubic 應用
description_en = A concise Cubic app
description_ja = Cubic 向けのシンプルなアプリ
kindapp 表示前台应用，service 表示后台服务。社区项目不应使用 launcher。
category可选 game、weather、clock、media、tool。
catalog_scope社区提交填写 community；official 由 clocteck 官方维护。
entry / icon指向仓库内实际存在的 Lua 入口和 PNG 图标。
allow_webui只有需要设备 Web 管理页时才设为 true。
name_* / description_*建议至少提供简体中文、繁体中文、英文和日文。
Submit for review

准备好后，把 GitHub 地址发给我们

请发邮件到 sales@clocteck.com，标题建议使用“Cubic 社区应用提交 - 应用名称”。clocteck 团队会检查元数据、可安装性、基础安全性和设备兼容性；通过后将上架到社区应用。

  • 邮件中附上公开可访问的 GitHub 仓库地址
  • 说明应用用途、支持的交互方式和已测试的固件版本
  • 不要在仓库中提交密码、Token、私钥或其他敏感信息
