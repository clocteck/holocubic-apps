# App 发布检查清单

发布范围包括设备运行包、商店元数据、云端图标和介绍页；只验证源码或 ZIP 不等于发布成功。

## 1. 应用元数据 app.info

- [ ] name 设置默认显示名；需要多语言时填写 name_zh_cn、name_zh_tw、name_en 等，并核对启动器与商店实际显示。
- [ ] author 填原作者姓名，不能只写在 info.html 或 README 中。
- [ ] entry 指向存在的 Lua 入口；icon 指向包内原始图片，例如 main.png。
- [ ] version、kind、category、catalog_scope、description 与实际功能一致。
- [ ] 介绍页、运行时版本与 app.info 一致；已发布版本有变更时遵循发布系统版本管理要求。
- [ ] 保留原作者署名、上游地址及代码/素材各自的许可证。

示例：

```ini
name = DSH-PET
name_zh = 大肥鱼
name_zh_cn = 大肥鱼
name_zh_tw = 大肥魚
name_zh_hant = 大肥魚
name_en = DSH-PET
author = chicochol
kind = app
category = tool
catalog_scope = community
entry = main.lua
icon = main.png
version = 1.5.1
```

## 2. 手柄与退出

- [ ] 明确哪些功能支持手柄：方向、确认、返回、翻页、退出等；仅支持退出不能宣称全功能手柄支持。
- [ ] 按键位与实际输入服务匹配。hidpad 的 ble-main：SELECT=4096、HOME=32768；不是所有手柄协议的通用定义。
- [ ] SELECT/HOME 能正常退出；设备自身 HOME 退出也正常。
- [ ] 检查单击边沿、长按、连按、断连/重连、无手柄状态，避免重复触发或断连残留按键触发。
- [ ] 退出时停止连接和播放，注销定时器、按键/事件回调，并释放界面、字体及模块拥有的资源。
- [ ] 至少做一次真机手柄测试；模拟输入只能证明逻辑，不能替代硬件验证。记录设备固件和输入服务版本。

## 3. 资源路径与安装目录

- [ ] 不硬编码开发机路径、旧应用 ID 或某个固定的 /sd/apps/<旧ID>/ 作为资源唯一地址。
- [ ] 动画清单使用包内相对路径；运行时通过当前应用目录解析为设备可访问路径。
- [ ] 固件需要绝对路径时，可动态拼接当前应用根目录；这不等于硬编码固定安装目录。
- [ ] 图标、字体、动态模块、GIF、音效、配置读写及 WebUI 路由都使用正确根目录。
- [ ] 换一个安装 ID 测试加载、资源预览、保存和重启，不能只测试默认 ID。
- [ ] 系统共享路径（例如 /sd/apps/settings.json）作为明确的系统接口保留，不应机械替换。
- [ ] 配置迁移、删除皮肤后的默认值及回退路径可用；清单不引用已删除文件。
- [ ] 注意路径大小写、空格、中文、URL 编码和目录遍历防护。
- [ ] 升级覆盖不代表旧文件已删除；回收资源前先备份个人配置，只清理明确属于该应用的废弃文件。

## 4. 图标和 info.html

- [ ] main.png 为可解码图片，大小/格式符合设备与商店要求，并实际包含在发布包中。
- [ ] app.info 的 icon 是相对文件名；不要把 Base64 data URI 填入需要文件路径的字段。
- [ ] info.html 放在运行包根目录，作为紧凑嵌入页，不是完整营销落地页。
- [ ] 使用原始 main.png 的 Base64 data URI 内嵌图标，不重绘，不用外链、Blob 或 ObjectURL。
- [ ] 页面说明真实的功能、按键、退出方式、电脑端依赖和安装方法。
- [ ] 名称、作者、项目地址、版本和安装大小正确；页底保留许可证信息。
- [ ] 手机宽度和启动器弹窗无横向溢出、遮挡，背景与主题符合要求。
- [ ] 本项目发布服务按固定文件名 info.html 读取，不需要编造 info/info_html 等 app.info 字段。
- [ ] 商店卡片/通用发布页使用独立图标接口；info.html 内嵌图标成功不代表商店图标成功。

## 5. 多语言（声明支持时必须检查）

- [ ] 应用元数据中的名称和描述与语言一致。
- [ ] info.html 的标题、正文、按钮、aria-label、图片 alt 和安装说明一起切换。
- [ ] 检查设备界面及配置页的文案、字体覆盖和长文本布局。
- [ ] 检查默认语言、系统语言跟随及未知语言回退；不宣称未实现的语言支持。

## 6. 打包、上传与线上验收

- [ ] 解压最终安装包，核对根目录层级、entry、main.png、info.html、作者、版本和全部资源。
- [ ] 排除个人配置、密钥、日志、缓存和构建临时文件；包含必要许可证。
- [ ] 语法、资源引用、功能回归、包完整性和校验和验证通过。
- [ ] Git 推送和商店发布是两回事：重新导入/发布后，确认云端实际使用新的提交与包。
- [ ] 检查线上 manifest：应用 ID、版本、entry、icon、文件清单和下载地址。
- [ ] 检查目录/description.json 的作者元数据，实际卡片不再回退为“社区开发者”。
- [ ] GET /download/apps/<id>/icon?v=<version> 返回 200、正确图片 Content-Type，且可解码。
- [ ] GET /v1/apps/<id>/description.html 返回 200 和真正的 info.html，而不是错误 JSON。
- [ ] 在商店点击详情，确认出现自定义介绍页，而不是带 Published at/package.tar 的通用回退页。
- [ ] 图标和介绍页同时 404 时，检查服务器应用库来源、发布 ID 与文件目录映射；包清单有文件不代表运行时读取接口能找到它。
- [ ] 完成浏览器检查和真机安装测试后才报告“发布验证通过”；明确标注尚未完成的项目。

## 发布记录

记录提交、版本、源包/安装包大小、SHA256、线上接口结果、测试设备及未完成项。
不要把本地测试通过、GitHub 推送成功、商店发布成功和真机验证通过混为一谈。
