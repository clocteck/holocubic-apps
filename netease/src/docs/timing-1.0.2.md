# 1.0.2：单调计时溢出修复

## 现场问题

QQ 音乐 1.0.1 的播放地址请求在联网开始前排队超时，计时字段为负数。
设备 Lua 使用 32 位整数和 32 位浮点数。旧 `transport.clock` 将微秒累计在整数中，
约 2147.484 秒（35 分 47 秒）后溢出，导致 HTTP 的 `not_before` 截止时间无法满足。
网易云使用相同代码，具有同样风险。

## 修改

- 两款应用的 `package/transport.lua` 均以秒、毫秒、微秒余数分段累计。
- 将 unsigned 32 位微秒差值拆成两个 16 位段，再缩放到毫秒，所有中间整数不溢出。
- 不用 float32 累加微小增量，避免长时间后增量被舍入、计时停止。
- 前 2,000,000 秒（约 23 天）返回精确整数毫秒，同时给截止时间加法留出超过一天的余量。
  更长时间从分段计数派生浮点读数，保持向前推进，但精度随 float32 数值增大而降低。
- 硬件微秒计数完整周期约 71.6 分钟，必须在每个周期内至少采样一次；
  应用现有 100ms 定时器满足此条件。不改变系统时间或登录授权所用 Unix 时间。
- 应用清单、说明页、User-Agent、原生模块版本统一为 1.0.2。
  QQ 1.0.1 的扫码授权修复全部保留。

## 验证

`src/tests/test_clock.lua` 同时运行于普通主机测试和固件同配置的 int32/float32 Lua。
运行 `src/tests/test_clock_32bit.ps1`，可通过 `-LuaSource` 指定本地固件 Lua 源码目录，
通过 `-VcVars` 指定 Visual Studio 环境脚本。仅在 app 的忽略 build 目录生成测试文件，
不修改固件源码。测试 runner 强制检查两种 Lua 数值类型均为 4 字节。

覆盖：
- 有符号边界、硬件计数回绕、35.8/71.6 分钟边界；
- 微秒余数保留、高位为 1 的无符号差值；
- 加速模拟 7 天后的 1ms 小增量、整数/浮点切换及截止时间余量、30 天计时推进；
- 真正的 transport 调度、200ms 冷却及 10s 排队超时跨越旧溢出点。

旧 clock 函数在同一 32 位测试中可复现失败，新 clock 两款均通过。
以上为加速模拟，不声称做过连续 30 天实机运行。
两款动态模块重建成功；网易云 32 项、QQ 音乐 31 项应用测试通过；
三个网页测试套件、两款原生内存测试（各 100 次创建/销毁）通过。

本次发布 package 和 src 到云端，不自动重启或改写设备上的账号数据。
设备更新后需退出并重新打开应用，使新的计时函数生效。
